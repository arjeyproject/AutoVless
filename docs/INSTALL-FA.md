# آموزش نصب AutoVless از صفر تا صد — سرور مجازی + داکر

این راهنما طوری نوشته شده که کسی که **هیچ تجربه‌ای از سرور و داکر ندارد** هم بتواند قدم‌به‌قدم ربات و مینی‌اپ را بالا بیاورد و شروع به ارائه خدمات به کاربران کند. همه دستورها را فقط کپی و پیست کنید؛ هر جا باید چیزی را با مقدار خودتان عوض کنید، با عبارت «به جای ...» گفته شده است.

سازه رسمی این راهنما **Ubuntu 22.04 یا 24.04** است. حداقل سخت‌افزار پیشنهادی: ۱ هسته CPU، ۱ گیگابایت RAM، ۱۰ گیگابایت فضای خالی.

## معماری: چه چیزی راه می‌اندازید؟

```text
کاربر تلگرام
   │  /start، /app
   ▼
ربات تلگرامی (کانتینر داکر روی سرور شما)
   ├── موتور ربات: منوها، ساخت کانفیگ، وایرگارد/وارپ، QR
   ├── API + مینی‌اپ: روی دامنه خودتان با HTTPS سرو می‌شود
   ├── درگاه پرداخت: زرین‌پال (callback روی دامنه شما) + استارز تلگرام
   └── اسکنرها: آی‌پی تمیز، رله proxyIP، اندپوینت وارپ
                │
                ▼
        پنل VLESS هر کاربر روی «اکانت کلادفلر خود کاربر» ساخته می‌شود
        (ترافیک کاربران از سرور شما عبور نمی‌کند)
```

سه نکته که قبل از شروع باید بدانید:

1. **پنل‌ها روی اکانت کلادفلر خود کاربرها ساخته می‌شوند.** هر کاربر یک API Token کلادفلر به مینی‌اپ می‌دهد و ورکر (Pages) روی حساب خودش دیپلوی می‌شود. سرور شما فقط مدیر و درگاه است؛ بار ترافیک VPN روی سرور شما نیست.
2. **دامنه HTTPS الزامی است** برای مینی‌اپ و برای بازگشت پرداخت زرین‌پال. دامنه رایگان هم کافی است (مثلاً از Cloudflare Registrar یا سرویس‌های دامنه رایگان)، ولی باید بتوانید رکورد DNS آن را ویرایش کنید.
3. **پرداخت اختیاری است.** تا وقتی در پنل مدیریت روشنش نکنید، ربات برای همه باز است. هر وقت خواستید، با چند دکمه داخل خود ربات روشن می‌شود.

## گام ۱ — خرید سرور مجازی (VPS)

- **لوکیشن:** هر جایی که به تلگرام و کلادفلر دسترسی باز دارد (آلمان، فنلاند، هلند، انگلستان، آمریکا و…). لوکیشن سرور روی کیفیت کانفیگ کاربران اثر مستقیم ندارد، چون ترافیک VPN از سرور شما رد نمی‌شود؛ سرور فقط ربات و API را نگه می‌دارد.
- **مشخصات:** ۱ vCPU / ۱GB RAM / ۱۰GBdisk برای تا چند صد کاربر کافی است. اگر تعداد کاربران بالا رفت، ۲GB RAM بخرید.
- **سیستم‌عامل:** موقع ساخت سرور، ایمیج **Ubuntu 22.04 LTS** یا **Ubuntu 24.04 LTS** را انتخاب کنید.
- بعد از ساخت، شرکت hosting دو چیز به شما می‌دهد: **IP سرور** (مثل `203.0.113.10`) و **رمز root** (یا یک کلید SSH).

## گام ۲ — اتصال به سرور با SSH

### ویندوز

1. منوی Start را باز کنید و بنویسید **PowerShell**، Enter بزنید.
2. این دستور را با IP خودتان بنویسید:
   ```bash
   ssh root@203.0.113.10
   ```
3. اولین بار می‌پرسد `Are you sure you want to continue connecting?` — بنویسید `yes` و Enter.
4. رمز root را پیست کنید (موقع تایپ چیزی دیده نمی‌شود، طبیعی است) و Enter.

### مک یا لینوکس

ترمینال را باز کنید و همان `ssh root@203.0.113.10` را بزنید.

### موبایل

اپ رایگان **Termius** را نصب کنید → New Host → آدرس IP، یوزر `root`، رمز → Connect.

اگر در هر مرحله گیر کردید، پیام خطا را کپی کنید؛ در بخش [عیب‌یابی](#عیبیابی) جدول راه‌حل هست.

## گام ۳ — آماده‌سازی سرور

همین دو دستور را بزنید (چند دقیقه طول می‌کشد):

```bash
apt update && apt upgrade -y
apt install -y curl git ca-certificates
```

فایروال را باز کنید (پورت ۲۲ برای SSH، ۸۰ و ۴۴۳ برای HTTPS):

```bash
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
```

> اگر شرکت hosting خودش فایروال بیرونی دارد (مثل Security Group)، همان‌جا هم پورت‌های ۲۲، ۸۰ و ۴۴۳ را باز کنید.

## گام ۴ — ساخت ربات در BotFather و گرفتن شناسه مدیر

### توکن ربات

1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بدهید.
2. دستور `/newbot` را بفرستید.
3. یک نام نمایشی بدهید (مثلاً «AutoVless من»).
4. یک یوزرنیم که به `bot` ختم می‌شود بدهید (مثلاً `myshop_vless_bot`).
5. BotFather یک توکن شبیه `1234567890:AAH3k9...` می‌دهد. **این را کپی و در جای امن ذخیره کنید.** این توکن را به هیچ‌کس نشان ندهید.

### شناسه عددی مدیر

1. به [@userinfobot](https://t.me/userinfobot) پیام بدهید؛ عدد `Id` را کپی کنید (مثلاً `123456789`).
2. همین عدد در `ADMIN_IDS` قرار می‌گیرد. برای چند مدیر، با کاما جدا کنید: `123456789,987654321`.

### اختیاری: فعال کردن پرداخت استارز

برای دریافت استارز تلگرام فقط لازم است در BotFather دستور `/mybots` → ربات شما → **Payments** را ببینید؛ Telegram Stars نیازی به provider بیرونی ندارد و در ربات ما بدون هیچ تنظیمی کار می‌کند.

## گام ۵ — دامنه و اتصال DNS

1. یک دامنه بخرید یا داشته باشید (مثلاً `mydomain.com`). لازم نیست رکورد دیگری داشته باشد.
2. یک **زیردامنه** برای ربات اختصاص دهید، مثلاً `bot.mydomain.com`. (استفاده از زیردامنه جدا بهتر است چون می‌توانید بعداً وب‌سایت اصلی را روی همان دامنه بالا بیاورید.)
3. در پنل DNS (اگر دامنه روی Cloudflare است، از تب **DNS**):
   - یک رکورد **A** بسازید:
     - **Name:** `bot` (یعنی `bot.mydomain.com`)
     - **IPv4 address:** IP سرور شما، مثلاً `203.0.113.10`
     - **Proxy status:** فعلاً **DNS only** (ابر خاکستری). Caddy خودش گواهی HTTPS می‌گیرد؛ ابر نارنجی (Proxied) مانع صدور گواهی می‌شود. بعد از بالا آمدن سرویس می‌توانید Proxied کنید.
4. صبر کنید تا DNS ثبات کند (معمولاً کمتر از چند دقیقه). تست:
   ```bash
   ping bot.mydomain.com
   ```
   اگر IP برگشتی IP سرور شما بود، آماده‌اید.

## گام ۶ — نصب خودکار (توصیه‌شده)

یک دستور، همه‌چیز: داکر، کد، `.env`، بیلد و استارت.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/arjeyproject/AutoVless/main/install.sh)
```

اسکریپت چند سوال می‌پرسد:

| سوال | چه بدهید |
|---|---|
| `Bot token from @BotFather` | توکن ربات از گام ۴ |
| `Your numeric Telegram id` | شناسه عددی شما (چند نفر؟ با کاما) |
| `Support link` | لینک پشتیبانی؛ Enter یعنی پیش‌فرض |
| `Your domain ... (empty to skip)` | `bot.mydomain.com` |

اسکریپت خودش داکر را نصب می‌کند، `SECRET_KEY` تصادفی می‌سازد، `WEBAPP_URL` و `PUBLIC_URL` را روی دامنه شما می‌گذارد و کانتینر را بالا می‌آورد. بعد از تمام شدن، پیام سبز «AutoVless is running» را می‌بینید.

**برای نصب بدون دامنه:** در سوال دامنه فقط Enter بزنید؛ ربات بالا می‌آید ولی مینی‌اپ و پرداخت زرین‌پال تا وقتی دامنه و HTTPS راه نیفتد کار نمی‌کنند (استارز کار می‌کند). بعداً در `.env` مقدارها را بدهید و یک بار ری‌استارت کنید.

## گام ۷ — نصب دستی و جدول کامل تنظیمات

اگر می‌خواهید خودتان همه‌چیز را کنترل کنید:

```bash
git clone https://github.com/arjeyproject/AutoVless.git /opt/autovless
cd /opt/autovless
cp .env.example .env
nano .env        # یا vi .env
```

حداقل این‌ها را پر کنید:

```env
BOT_TOKEN=توکن_ربات
ADMIN_IDS=123456789
SECRET_KEY=خروجی_دستور_زیر
WEBAPP_URL=https://bot.mydomain.com
PUBLIC_URL=https://bot.mydomain.com
```

```bash
openssl rand -hex 32     # خروجی را در SECRET_KEY بگذارید
mkdir -p data && chown -R 10001:10001 data
docker compose build --pull
docker compose up -d
```

### جدول متغیرهای مهم `.env`

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `BOT_TOKEN` | — | **الزامی.** توکن BotFather |
| `ADMIN_IDS` | — | **الزامی.** شناسه مدیران، با کاما |
| `SECRET_KEY` | خودکار | کلید امضای لینک‌ها؛ طولانی و تصادفی |
| `WEBAPP_URL` | — | آدرس HTTPS مینی‌اپ (دامنه شما) |
| `PUBLIC_URL` | =WEBAPP_URL | دامنه‌ای که زرین‌پال به آن برمی‌گردد |
| `BRAND` | AutoVless | نام نمایشی ربات و مینی‌اپ |
| `SUPPORT_URL` / `CHANNEL_URL` | — | لینک پشتیبانی/کانال در منوها |
| `DEPLOY_TARGET` | `pages` | ساخت پنل روی Cloudflare **Pages** (مقدار `workers` برمی‌گردد به ورکر قدیمی) |
| `TLS_CONFIG_COUNT` / `HTTP_CONFIG_COUNT` | ۵ / ۳ | تعداد کانفیگ TLS/HTTP هر پنل |
| `HTTPUPGRADE` / `XHTTP` | true | پروتکل‌های رایگان اضافه روی هر اشتراک |
| `WARP_ENABLED` | true | بخش وایرگارد/وارپ |
| `ENDPOINT_SCAN_ENABLED` | false | موتور خود-ترمیم استخر آی‌پی (اسکن دوره‌ای + curator + autopilot). حتی خاموش هم باشد، موقع ساخت هر پنل یک اسکن لحظه‌ای برای پر کردن استخر اجرا می‌شود |
| `WARP_SCAN_ENABLED` | false | اسکن دوره‌ای اندپوینت وارپ. خاموش بودنش یعنی اندپوینت‌ها از فایل‌های seed و استخر اولیه انتخاب می‌شوند |
| `STORE_TOKENS` | false | نگه‌داری رمز توکن کلادفلر کاربر برای rebuild خودکار. روشن کردنش autopilot پنل‌ها را قوی‌تر می‌کند |
| `API_PORT` | 8088 | پورت داخلی API (پشت Caddy) |
| `LOG_LEVEL` | INFO | برای عیب‌یابی `DEBUG` کنید |

فایل `.env.example` داخل پروژه برای هر متغیر توضیح کامل دارد.

## گام ۸ — استارت و بررسی سلامت

```bash
cd /opt/autovless
docker compose ps          # باید STATUS: Up باشد
docker compose logs -f     # لاگ زنده؛ با Ctrl+C خارج شوید
```

حالا نصب HTTPS با Caddy (یک بار، برای همیشه):

```bash
apt install -y caddy
nano /etc/caddy/Caddyfile
```

این را داخلش بگذارید (به جای `bot.mydomain.com` دامنه خودتان):

```caddy
bot.mydomain.com {
    reverse_proxy 127.0.0.1:8088
}
```

```bash
systemctl reload caddy
curl -I https://bot.mydomain.com/health
```

خروجی `HTTP/2 200` یعنی همه‌چیز درست است. در تلگرام به ربات `/start` بدهید؛ ربات باید پیام خوش‌آمد بدهد و یک گزارش راه‌اندازی به مدیر برسد.

## گام ۹ — وصل کردن مینی‌اپ به ربات

1. در BotFather: `/mybots` → ربات خودتان → **Bot Settings** → **Menu Button** → **Configure menu button**.
2. اول آدرس را بفرستید: `https://bot.mydomain.com`
3. بعد متن دکمه را بفرستید: مثلاً `🚀 باز کردن اپ`
4. تمام. الان کنار کادر نوشتن ربات شما یک دکمه آبی «🚀 باز کردن اپ» دارد.

راه سریع‌تر: کافی است کاربر در ربات دستور `/app` بزند؛ خود ربات دکمه باز کردن مینی‌اپ را نشان می‌دهد.

## گام ۱۰ — نصب مینی‌اپ (دو روش)

### روش ۱ — روی دامنه خودتان (پیش‌فرض و توصیه‌شده)

چیزی برای نصب کردن نیست: **مینی‌اپ داخل همان کانتینر داکر بسته شده** و Caddy آن را روی `https://bot.mydomain.com` سرو می‌کند. هر بار `docker compose up -d --build` بزنید، آخرین نسخه مینی‌اپ از گیت‌هاب داخل ایمیج تازه می‌شود.

اگر خواستید ظاهرش را ویرایش کنید بدون rebuild، در `docker-compose.yml` این خط را از کامنت دربیاورید:

```yaml
volumes:
  - ./webapp:/app/webapp:ro
```

بعد هر تغییر در فایل‌های `webapp/` با یک `docker compose restart` روی دامنه اعمال می‌شود.

### روش ۲ — گیت‌هاب پیجز (پشتیبان، خودکار)

مخزن یک **GitHub Actions** آماده دارد (`.github/workflows/pages.yml`): هر بار چیزی در پوشه `webapp/` به شاخه `main` پوش شود، مینی‌اپ خودکار روی آدرس زیر منتشر می‌شود:

```text
https://arjeyproject.github.io/AutoVless/
```

اگر مالک مخزن هستید، فعال بودن Pages را در تب **Settings → Pages** مخزن چک کنید (Source باید `GitHub Actions` باشد). اولین پوش بعد از فعال‌سازی، دیپلوی را انجام می‌دهد.

**نکته مهم روش ۲:** این نسخه استاتیک است و کد API ندارد؛ باید به ربات بگویید API کجاست. آدرس مینی‌اپ را با پارامتر `api` به BotFather بدهید:

```text
https://arjeyproject.github.io/AutoVless/?api=https://bot.mydomain.com
```

خود مینی‌اپ هم اگر API پیدا نکند، صفحه خطا نشان می‌دهد و همین راه‌حل را پیشنهاد می‌دهد. برای عملکرد کامل (پرداخت، امضا و…)، **روش ۱ را ترجیح بدهید**؛ روش ۲ برای تست و شروع سریع خوب است.

## گام ۱۱ — تنظیم پرداخت و زرین‌پال

از این جا به بعد همه‌چیز از **داخل خود ربات** تنظیم می‌شود — نه فایل، نه ری‌استارت.

### ۱۱-۱) گرفتن Merchant ID از زرین‌پال

1. در سایت [zarinpal.com](https://www.zarinpal.com) ثبت‌نام کنید (شماره موبایل + ایمیل).
2. **احراز هویت** را کامل کنید (تصویر مدارک). درگاه واقعی بدون احراز هویت فعال نمی‌شود.
3. از پنل کاربری، بخش **پذیرندگی / درگاه پرداخت**، یک درگاه جدید بسازید.
4. یک **مرچنت آیدی** به شکل UUID می‌گیرید، ۳۶ کاراکتر با خط تیره:
   ```text
   xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
   ```
5. همین رشته را فقط داخل ربات وارد کنید؛ ربات خودش بعد از ذخیره، پیام حاوی مرچنت را از چت پاک می‌کند.

### ۱۱-۲) تنظیم داخل ربات (پنل مدیریت)

در ربات: **پنل مدیریت → 💳 درگاه پرداخت ورود**

| دکمه | کارش |
|---|---|
| 🔛 روشن/خاموش پرداخت | کلید اصلی. خاموش = ربات برای همه رایگان |
| 🔀 درگاه | بین `stars`، `zarinpal` و `هر دو` می‌چرخد |
| 💰 مبلغ (تومان) | مبلغ اشتراک؛ مثلاً `50000` |
| ⭐️ مبلغ استارز | قیمت اشتراک به Telegram Stars؛ مثلاً `100` |
| 📅 اعتبار (روز) | چند روز اعتبار دارد؟ `0` = دائمی |
| 🏦 مرچنت زرین‌پال | همان UUID مرحله قبل |
| 🧪 حالت تست (Sandbox) | روشن = پرداخت آزمایشی بدون پول واقعی |
| 📜 آخرین پرداخت‌ها | ۱۲ پرداخت موفق آخر با مبلغ و کاربر |
| ✅ دستی اعطا | `شناسه‌کاربر [روز]` — اعتبار رایگان بدهید |
| ⛔️ لغو اشتراک | `شناسه‌کاربر` — دسترسی را قطع می‌کند |

تِیم تنظیم کامل زرین‌پال: درگاه را روی `zarinpal` یا `both` بگذارید → مرچنت را بدهید → مبلغ و اعتبار را تعیین کنید → **حالت تست را روشن کنید** و یک پرداخت آزمایشی بزنید → بعد از موفقیت، حالت تست را خاموش کنید.

### ۱۱-۳) آدرس بازگشت (callback)

زرین‌پال بعد از پرداخت، کاربر را به این آدرس برمی‌گرداند:

```text
https://bot.mydomain.com/pay/zarinpal/callback
```

ربات خودش این آدرس را از `PUBLIC_URL` می‌سازد و در همان صفحه پنل پرداخت نمایش می‌دهد؛ **نیازی به ثبت دستی در پنل زرین‌پال نیست.** فقط باید `PUBLIC_URL` یک دامنه HTTPS واقعی باشد. تأیید نهایی پرداخت سرور-به-سرور انجام می‌شود و حتی اگر کاربر صفحه را رفرش کند، دوباره اعتبار اضافه نمی‌شود (idempotent).

### ۱۱-۴) تنظیم پرداخت از مینی‌اپ

همان تنظیمات از مینی‌اپ هم قابل تغییر است: **بیشتر → پنل مدیریت → 💳 درگاه پرداخت ورود**. روشن/خاموش، درگاه، مبلغ، مرچنت و حالت تست، همگی از همان‌جا. تغییرات در ربات و مینی‌اپ بلافاصله یکی است، چون هر دو روی یک دیتابیس و یک ماژول پرداخت کار می‌کنند.

### ۱۱-۵) تجربه کاربر پرداخت‌کننده

- ربات: کاربر غیرمشترک فقط صفحه پرداخت می‌بیند؛ با دکمه «پرداخت با کارت بانکی» لینک زرین‌پال باز می‌شود و بعد از برگشت، دکمه «پرداخت کردم، بررسی کن» بلافاصله منو را باز می‌کند.
- مینی‌اپ: کارت «🔐 اشتراک ورود» بالای صفحه ظاهر می‌شود؛ پرداخت زرین‌پال در مرورگر باز می‌شود و استارز با `openInvoice` داخل خود تلگرام پرداخت می‌شود. بعد از پرداخت، مینی‌اپ تا ۱۲۰ ثانیه هر ۳ ثانیه وضعیت را چک می‌کند و خودش قفل را باز می‌کند.
- مدیرها هرگز از پرداخت عبور نمی‌کنند و صفحه پرداخت برایشان نمایش داده نمی‌شود.
- پرداخت زمان‌دار تجمعی است: اگر ۱۰ روز اعتبار مانده باشد و کاربر دوباره ۳۰ روزه بخرد، اعتبارش ۴۰ روز می‌شود؛ روزهای قبلی نمی‌سوزند.

## به‌روزرسانی، بکاپ و بازگردانی

### به‌روزرسانی

```bash
cd /opt/autovless
git pull
docker compose up -d --build
```

### بکاپ (کاربران، تنظیمات، پنل‌ها)

```bash
cd /opt/autovless
tar -czf autovless-backup-$(date +%F).tar.gz data .env
```

فایل بکاپ را جایی غیر از همین سرور نگه دارید (مثلاً با `scp` روی لپ‌تاپ خودتان):

```bash
scp root@203.0.113.10:/opt/autovless/autovless-backup-*.tar.gz .
```

### بازگردانی روی سرور جدید

```bash
# پروژه را با گام ۶ یا ۷ نصب کنید، بعد کانتینر را خاموش کنید:
docker compose down
tar -xzf autovless-backup-YYYY-MM-DD.tar.gz -C /opt/autovless
chown -R 10001:10001 /opt/autovless/data
docker compose up -d
```

## عیب‌یابی

| مشکل | علت معمول | راه‌حل |
|---|---|---|
| کانتینر مدام restart می‌شود | مجوز پوشه `data` | `chown -R 10001:10001 /opt/autovless/data` و `docker compose restart` |
| ربات اصلاً جواب نمی‌دهد | توکن اشتباه یا قطع شبکه سرور | `docker compose logs --tail=50`؛ خطای `Unauthorized` یعنی توکن غلط است |
| مینی‌اپ باز نمی‌شود | `WEBAPP_URL` غلط، HTTPS نیست، یا DNS ست نشده | `curl -I https://bot.mydomain.com/health` باید 200 بدهد؛ رکورد A و Proxy status را چک کنید |
| `HTTP/2 200` نمی‌گیرید | Caddy یا فایروال | `systemctl status caddy` و `ufw status` را چک کنید؛ پورت ۸۰ باز باشد (صدور گواهی) |
| زرین‌پال «درگاه پاسخ نداد» | مرچنت غلط یا بدون احراز هویت | مرچنت را دوباره وارد کنید؛ وضعیت احراز هویت در پنل زرین‌پال |
| زرین‌پال می‌گوید callback نامعتبر | `PUBLIC_URL` https نیست یا دامنه با رکورد DNS نمی‌خواند | آدرس callback نمایش‌داده‌شده در پنل پرداخت را باز کنید؛ باید صفحه ربات باز شود |
| پرداخت موفق ولی قفل باز نشد | بازگشت بدون `Status=OK` یا قطع لحظه‌ای اینترنت کاربر | کاربر «پرداخت کردم، بررسی کن» را بزند؛ تراکنش در «آخرین پرداخت‌ها» باید `paid` باشد |
| استارز invoice خطا می‌دهد | ربات استارز را تنظیم نکرده | در پنل پرداخت، درگاه را روی `stars` یا `both` بگذارید و مبلغ استارز > ۰ باشد |
| کانفیگ‌های کاربر خالی شد | اندپوینت‌ها فیلتر شده‌اند | دکمه «آی‌پی تازه» در مینی‌اپ؛ برای خود-ترمیم دائمی، `ENDPOINT_SCAN_ENABLED=true` |
| وایرگارد روی iOS وصل نمی‌شود | اپ رسمی WireGuard نویز Amnezia را نمی‌فهمد | در iOS فایل **AmneziaWG** را بردارید (ربات خودش پیش‌فرضش را می‌دهد) |
| ساعت سرور به‌هم ریخته و امضای مینی‌اپ رد می‌شود | drift ساعت | `apt install -y systemd-timesyncd && systemctl restart systemd-timesyncd` |
| IPv6 وارپ همیشه صفر می‌ماند | شبکه bridge داکر IPv6 ندارد | طبق توضیح `docker-compose.yml` یا `network_mode: host` بمانید یا IPv6 داکر را فعال کنید |

برای دیدن زنده هر اتفاق: `docker compose logs -f --tail=200`.

## چک‌لیست امنیتی

- [ ] `SECRET_KEY` طولانی و تصادفی است و در گیت‌هاب نیست.
- [ ] فایل `.env` با `chmod 600` قفل است و هرگز در چت/اسکرین‌شات نمی‌آید.
- [ ] توکن BotFather فقط روی سرور است؛ اگر لو رفت، در BotFather → `/revoke` عوضش کنید.
- [ ] `ADMIN_IDS` فقط خودتان (و مدیران واقعی) هستند.
- [ ] SSH با رمز ضعیف باز نماند؛ ترجیحاً کلید SSH و در صورت امکان غیرفعال کردن ورود root با رمز.
- [ ] مرچنت آیدی فقط داخل ربات وارد می‌شود و ربات آن را از چت پاک می‌کند.
- [ ] بکاپ دوره‌ای از `data/` و `.env` جای امن.
- [ ] اگر `STORE_TOKENS=true` کردید، بکاپ‌ها را محرمانه‌تر نگه دارید (دیتابیس حاوی توکن‌های رمزشده کلادفلر کاربران است).

## سوال‌های پرتکرار

**آیا ترافیک VPN کاربران از سرور من رد می‌شود؟**
نه. پنل هر کاربر روی اکانت کلادفلر خودش ساخته می‌شود و ترافیک از edge کلادفلر می‌گذرد. سرور شما فقط ربات، مینی‌اپ و اسکنرها را نگه می‌دارد.

**چند کاربر را می‌توانم با سرور ۱ گیگابایتی پشتیبانی کنم؟**
چند صد کاربر بدون مشکل؛ مصرف RAM کانتینر سقف ۶۴۰ مگابایت دارد. گلوگاه بعدی تعداد اسکن‌هاست، نه تعداد کاربران.

**پرداخت را روشن کنم، کاربرهای قبلی چه می‌شوند؟**
هر کس قبل از روشن شدن پرداخت وارد شده، تا وقتی اشتراک ندارد صفحه پرداخت را می‌بیند. اگر می‌خواهید اولین گروه رایگان باشند، از «دستی اعطا» برایشان اعتبار بدهید (مثلاً `123456789 3650`).

**دو درگاه با هم چطور کار می‌کنند؟**
با انتخاب `both`، کاربر خودش بین کارت بانکی (زرین‌پال) و استارز تلگرام انتخاب می‌کند؛ هر دو به همان یک اعتبار وصل‌اند.

**دامنه ندارم، چه کنم؟**
ربات و استارز بدون دامنه کار می‌کنند. برای زرین‌پال و مینی‌اپ دامنه HTTPS لازم است. می‌توانید موقتاً مینی‌اپ را با روش گیت‌هاب پیجز بالا بیاورید و برای پرداخت، دامنه رایگان بگیرید.

**می‌خواهم فقط بخش وایرگارد را بدهم، بقیه را ببندم؟**
از پنل مدیریت ربات گزینه‌های WARP و منوی پروتکل‌ها قابل کنترل است؛ هر پروتکل انتخابی است و کاربر هر کدام را خواست جدا برمی‌دارد یا همه را یکجا از لینک اشتراک می‌گیرد.

پس از طی کردن گام‌های ۱ تا ۱۱، سیستم شما کامل است: ربات فعال، مینی‌اپ روی دامنه، پرداخت تنظیم، و کانفیگ‌ها خودشان را تازه نگه می‌دارند. برای تغییر ظاهر یا متن‌های ربات، از پنل مدیریت شروع کنید؛ تقریباً همه‌چیز از همان‌جا قابل تنظیم است.
