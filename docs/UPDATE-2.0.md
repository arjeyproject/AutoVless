# آپدیت به AutoVless 2.0

این نسخه چهار تغییر بزرگ دارد. اول بخوان چه چیزی عوض شده، بعد دستورهای آپدیت را بزن.

---

## ۱. رفع مشکل جیمینای و آی‌پی ثابت خروجی

سه علت داشت و هر سه برطرف شد:

1. **لاگین گوگل و خود جیمینای از دو آی‌پی مختلف خارج می‌شدند.** فقط
   `gemini.google.com` در لیست مسیر AI بود و `accounts.google.com` نبود، پس ورود از
   یک آی‌پی کلادفلر و خود اپ از یک رله خارج می‌شد. گوگل این را «نشست دزدیده‌شده»
   می‌خواند و کاربر را بی‌نهایت به صفحه‌ی لاگین برمی‌گرداند. کل مسیر هویت گوگل
   (`accounts.google.com`، `apis.google.com`، `clients6.google.com`،
   `googleusercontent.com` و …) الان روی مسیر AI است. → `bot/aipin.py`
2. **رله جابه‌جا می‌شد.** ورکر بر اساس نام دامنه‌ی مقصد پین می‌کند، پس یک لیست چند‌تایی
   دوباره همان اختلاف را می‌سازد. حالا استخر AI هر پنل **دقیقاً یک رله** است؛ اگر آن رله
   بمیرد ورکر مثل قبل زنجیره‌ی عادی و سپس مسیر مستقیم را امتحان می‌کند، پس چیزی از
   پایداری کم نمی‌شود.
3. **رله در کشور اشتباه بود.** رله‌ها مکان‌یابی می‌شوند و پین از میان کشورهای مجاز
   انتخاب می‌شود؛ **اول آمریکا**، بعد کانادا/بریتانیا/آلمان/هلند/… و هرگز ایران، روسیه،
   چین و مشابه (چون خروجی آن‌ها ارور ریجن می‌دهد).

پین **ذخیره می‌شود** (جدول `ai_pins`، کلید = uuid پنل). قبلاً از لیست زنده‌ی رله‌ها
مشتق می‌شد و با هر تغییر استخر عوض می‌شد — همان رفتاری که این سایت‌ها به‌عنوان سوءاستفاده
می‌خوانند. حالا فقط وقتی عوض می‌شود که رله واقعاً مرده باشد.

> **مهم:** آی‌پی‌های عمومی proxyIP هر چند ساعت می‌سوزند. اگر آی‌پی آمریکای «بی‌قید و شرط
> ثابت» می‌خواهی، یک پروکسی استاتیک آمریکا بگیر و در `.env` بگذار:
> `AI_PROXY_IP=1.2.3.4` — این مقدار بر همه‌چیز اولویت دارد.

## ۲. قفل دعوت اجباری (پنل ادمین → 🔐 قفل دعوت)

روشن/خاموش + تعیین عدد با ادمین است. تا وقتی کاربر N نفر دعوت نکرده، هر دکمه‌ای بزند
یک صفحه‌ی زیبا با لینک اختصاصی، نوار پیشرفت و دکمه‌ی ارسال می‌بیند. دعوت خودت، دعوت
تکراری و اکانت‌هایی که قبلاً در ربات بوده‌اند شمرده نمی‌شوند.

## ۳. کانفیگ‌های رایگان (پنل ادمین → 🎈 کانفیگ رایگان)

یک ورکر AutoVless را به‌عنوان «سرور رایگان» ثبت می‌کنی (یا با یک دکمه پنل خودت را).
بعد از آن هر کاربر بدون اکانت کلادفلر می‌تواند VLESS، Trojan یا هر دو را بگیرد. آی‌پی
ورودی از همان استخر تمیز اسکن‌شده می‌آید و **قبل از تحویل هندشیک واقعی می‌دهد**؛ لینک
اشتراک هم لینک خود ورکر است، یعنی خودش تازه می‌شود. وایرگارد/وارپ از قبل رایگان بود.

## ۴. مینی‌اپ کامل

مینی‌اپ قدیمی فقط خواندنی بود. حالا یک API امضاشده دارد و همه‌ی کارها را انجام می‌دهد:
ساخت/بازسازی/حذف پنل توربو، اعمال آی‌پی تازه، پینگ، QR، ساخت وایرگارد برای هر دستگاه،
تروجان، کانفیگ رایگان، دعوت دوستان، دارک/لایت، فارسی/انگلیسی و پنل ادمین.
راهنمای صفر تا صد: [docs/MINIAPP.md](MINIAPP.md)

## دستورهای آپدیت

### داکر (روش نصب پیش‌فرض)

```bash
cd /opt/autovless            # یا هر جایی که نصب کرده‌ای
cp data/autovless.db data/autovless.db.bak   # پشتیبان، ۵ ثانیه وقت می‌گیرد
git pull
docker compose build --pull
docker compose up -d
docker compose logs -f --tail=80
```

مهاجرت دیتابیس **خودکار** است؛ جدول‌های `referrals`، `free_servers`، `free_grants`،
`ai_pins` و ستون‌های تازه‌ی `proxy_ips`/`users`/`panels` در همان بوت اول ساخته می‌شوند.
هیچ دستور دستی لازم نیست.

### بدون داکر (systemd / venv)

```bash
cd /opt/autovless
cp data/autovless.db data/autovless.db.bak
git pull
source .venv/bin/activate
pip install -r requirements.txt      # aiohttp اضافه شده
systemctl restart autovless
journalctl -u autovless -f
```

### متغیرهای تازه‌ی `.env` (همه اختیاری)

| متغیر | پیش‌فرض | کار |
|---|---|---|
| `WEBAPP_URL` | خالی | آدرس HTTPS مینی‌اپ. خالی باشد، دکمه‌ی مینی‌اپ نشان داده نمی‌شود |
| `API_ENABLED` | `1` | سرور مینی‌اپ. `0` یعنی خاموش |
| `API_HOST` | `0.0.0.0` | اینترفیس شنونده |
| `API_PORT` | `8088` | پورت سرور مینی‌اپ |
| `WEBAPP_DIR` | `webapp/` | مسیر فایل‌های استاتیک مینی‌اپ |
| `INIT_DATA_TTL` | `86400` | اعتبار امضای تلگرام به ثانیه |
| `AI_PROXY_IP` | خالی | آی‌پی ثابت خروجی AI. اگر پر باشد بر انتخاب خودکار اولویت دارد |

قفل دعوت و بخش رایگان متغیر `.env` ندارند؛ **از داخل پنل ادمین** تنطیم می‌شوند و در
دیتابیس ذخیره می‌مانند.

## چک‌لیست بعد از آپدیت

1. لاگ‌ها را ببین: پیام «is up» با خط‌های `free servers`، `invite lock` و `mini app` می‌آید.
2. `/menu` → پنل مدیریت → **🧠 مسیر AI** → دکمه‌ی **🌍 مکان‌یابی رله‌ها** را بزن.
   یک بار لازم است تا کشور رله‌ها شناخته شود (نتیجه یک هفته کش می‌شود).
3. همان صفحه باید «🇺🇸 آمریکا: عددی بزرگ‌تر از صفر» نشان بدهد. اگر صفر بود:
   `PROXY_IP_SOURCES` را بگذار کار کند یا `AI_PROXY_IP` را دستی پر کن.
4. پنل مدیریت → موتور → **اعمال خودکار** را بزن (یا صبر کن اتوپایلوت بیاید) تا هر پنل
   با پین تازه و لیست دامنه‌ی تازه دوباره آپلود شود. **بدون این مرحله ورکرها هنوز روی
   تنطیم قدیمی هستند.**
5. کاربر تستی: پنل → **🧠 AI** ← باید همه‌ی دامنه‌ها به یک رله پین شده باشند.
6. اگر قفل دعوت می‌خواهی: پنل مدیریت → 🔐 قفل دعوت → روشن + تعیین تعداد.
7. اگر کانفیگ رایگان می‌خواهی: پنل مدیریت → 🎈 کانفیگ رایگان → 🗂 ثبت پنل خودم.

## برگشت به نسخه‌ی قبل

```bash
cd /opt/autovless
git log --oneline -5          # هش قبل از آپدیت را بردار
git checkout <هش>
cp data/autovless.db.bak data/autovless.db
docker compose up -d --build
```

جدول‌های تازه به نسخه‌ی قدیمی آسیبی نمی‌زنند؛ فقط نادیده گرفته می‌شوند.

# English summary

* **Gemini fix.** The whole Google identity path now rides the AI route, each panel
  gets exactly one geolocated relay (US first), and that pin is stored per panel
  uuid instead of being derived from the live relay list. Set `AI_PROXY_IP` if you
  own a static address and want a hard guarantee.
* **Invite lock.** Admin panel → invite lock: switch it on, set the quota.
* **Free configs.** Register one AutoVless worker as a shared free server; users get
  real, handshake-verified VLESS/Trojan without a Cloudflare account.
* **Mini app.** Full read/write app behind a signed API. See `docs/MINIAPP.md`.

Update with `git pull && docker compose up -d --build`. Migrations run on boot.
After the update, press **Geolocate relays** once in the admin AI screen, then
**Apply** so every worker picks up the new bindings.
