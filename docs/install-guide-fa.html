ایده: چرا ارور منطقه می‌گیرید و چطور حل می‌شود

کانفیگ‌های VLESS این ربات روی Cloudflare Worker ساخته می‌شوند. مشکل این است که Worker نمی‌تواند مستقیم به سایت‌هایی که پشت Cloudflare هستند (مثل ChatGPT و Claude) وصل شود، و Gemini هم IP دیتاسنتر Cloudflare را که مدام عوض می‌شود مشکوک می‌داند و مدام لاگین می‌خواهد یا ارور منطقه می‌دهد.

راه‌حل: سرور اوبونتوی خودتان (که خارج از ایران است) یک رله خصوصی می‌شود. Worker فقط ترافیک سایت‌های هوش مصنوعی را به این رله می‌فرستد و رله آن را با IP ثابت سرور شما به سایت تحویل می‌دهد. نتیجه: ChatGPT و Gemini همیشه یک IP آلمان یا هلند یا آمریکا می‌بینند، نه IP ایران و نه IP چرخشی.

کاربرv2rayNG / Hiddify
IP تمیز کلادفلرورودی کانفیگ
Worker کاربرپنل VLESS
رله شما :8443فقط دامنه‌های AI
ChatGPT / GeminiIP ثابت سرور شما را می‌بیند

بقیه سایت‌ها مثل قبل مستقیم از Cloudflare می‌روند، پس حجم سرور شما فقط صرف هوش مصنوعی می‌شود. رله هم فقط نام دامنه‌های هوش مصنوعی را عبور می‌دهد، پس پروکسی باز و قابل سوءاستفاده نیست.

پیش‌نیازها

موردتوضیح
سرور مجازیUbuntu 22.04 یا 24.04، حداقل ۱ هسته و ۱ گیگ رم. حتماً خارج از ایران (آلمان، هلند، فنلاند یا آمریکا). کشور سرور همان کشوری است که ChatGPT و Gemini می‌بینند.

توکن رباتاز @BotFather با دستور /newbot.
آیدی عددی شمابه @userinfobot پیام بدهید، عدد Id را بردارید.

اتصال و آماده‌سازی سرور

به جای SERVER_IP آی‌پی سرورتان را بگذارید:

ssh root@SERVER_IP

به‌روزرسانی سیستم و تنظیم ساعت:

apt update && apt -y upgrade
apt -y install curl git nano ufw dnsutils
timedatectl set-timezone Asia/Tehran

اگر پیام ریستارت داد، reboot بزنید و دوباره وصل شوید.

۴

تنظیم دامنه prostoreshop.site

  1. وارد پنل DNS دامنه شوید (Cloudflare → دامنه → DNS → Records).
  2. یک رکورد A بسازید: Name = @، Content = آی‌پی سرور.
  3. در Cloudflare ابر را خاکستری (DNS only) کنید. برای گرفتن گواهی SSL لازم است.

تست (باید آی‌پی سرور را برگرداند):

dig +short prostoreshop.site
بعداً اختیاریاگر دامنه از داخل ایران باز نشد، بعد از گرفتن گواهی (مرحله ۷) ابر را نارنجی کنید و در SSL/TLS حالت Full (strict) را بگذارید.
۵

فایروال

فقط پورت‌های لازم باز می‌مانند. پورت 8088 (API داخلی ربات) عمداً بسته است.

ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 8443/tcp
ufw --force enable
ufw status
اول OpenSSHاگر پورت SSH شما غیر از 22 است، قبل از enable آن را هم باز کنید (ufw allow 2222/tcp) وگرنه دسترسی‌تان قطع می‌شود.

نصب ربات AutoVless

اسکریپت نصب، داکر را نصب می‌کند، پروژه را در /opt/autovless می‌گذارد و ربات را بالا می‌آورد:

curl -fsSL https://raw.githubusercontent.com/arjeyproject/AutoVless/main/install.sh -o install.sh
sudo bash install.sh

به سؤال‌ها این‌طور جواب دهید:

سؤالجواب
Bot token from @BotFatherتوکن ربات
Your numeric Telegram idآیدی عددی شما (چند ادمین: با کاما)
Support linkلینک پشتیبانی خودتان، یا Enter
Your domain for the mini appprostoreshop.site

تست: در تلگرام به ربات /start بدهید. یک پیام گزارش «is up» هم برای ادمین می‌آید. لاگ زنده:

cd /opt/autovless && docker compose logs -f --tail 50

با Ctrl+C از لاگ خارج شوید (ربات خاموش نمی‌شود).

۷

HTTPS و فعال‌سازی مینی‌اپ

تلگرام مینی‌اپ را فقط روی HTTPS باز می‌کند. این اسکریپت Caddy را نصب می‌کند، گواهی رایگان می‌گیرد و دامنه را به ربات وصل می‌کند. مقادیر WEBAPP_URL، PUBLIC_URL و API_HOST=127.0.0.1 را هم خودش در .env می‌نویسد:

cd /opt/autovless
sudo bash scripts/setup-miniapp.sh prostoreshop.site
docker compose up -d --build

تست (باید "ok": true برگرداند):

curl https://prostoreshop.site/api/health

در مرورگر هم https://prostoreshop.site را باز کنید؛ صفحه مینی‌اپ باید با قفل سبز بیاید (بیرون از تلگرام پیام احراز هویت می‌دهد که طبیعی است).

۸

رله IP ثابت برای ChatGPT و Gemini

این مهم‌ترین مرحله است. اسکریپت یک رله SNI روی پورت 8443 می‌سازد که فقط دامنه‌های هوش مصنوعی را عبور می‌دهد، و AI_PROXY_IP=IP_سرور:8443 را در .env می‌گذارد:

cd /opt/autovless
sudo bash scripts/setup-ai-relay.sh 8443

آخر اسکریپت یک تست خودکار اجرا می‌شود و باید چیزی شبیه این ببینید:

ip=203.0.113.25
loc=DE

ip باید دقیقاً IP سرور شما باشد و loc کشور سرور. اگر loc=IR بود یعنی سرور داخل ایران است و این روش برایش کار نمی‌کند.

چرا AI_PROXY_IP؟ربات به‌صورت پیش‌فرض از رله‌های عمومی استفاده می‌کند که ممکن است بمیرند یا کشورشان عوض شود. با AI_PROXY_IP همه کاربران برای همه سایت‌های هوش مصنوعی (و مسیر لاگین گوگل) از یک IP ثابت و مطمئن خارج می‌شوند و این تنظیم بر همه چیز اولویت دارد.

بررسی دستی مقدارها:

grep -E '^(AI_ROUTE|AI_PROXY_IP|WEBAPP_URL|PUBLIC_URL|API_HOST)=' /opt/autovless/.env

cd /opt/autovless

docker compose ps

در لاگ باید api listening on 127.0.0.1:8088 و is polling ببینید. پیام وضعیت ادمین در تلگرام هم خط mini app: https://prostoreshop.site را نشان می‌دهد.

دکمه مینی‌اپ در BotFather

  1. به @BotFather بروید و /mybots را بزنید، ربات را انتخاب کنید.
  2. Bot Settings → Menu Button → Configure menu button
  3. آدرس: https://prostoreshop.site و عنوان: پنل من
  4. اختیاری: /newapp برای ساخت لینک مستقیم t.me/YourBot/app با همان آدرس.

تست: در ربات /app بزنید یا دکمه منو را لمس کنید؛ مینی‌اپ داخل تلگرام باز می‌شود و نام شما را نشان می‌دهد.

۱۱

تحویل به کاربران

  1. کاربر در ربات یا مینی‌اپ گزینه ساخت پنل را می‌زند و توکن API کلادفلر خودش را می‌دهد (Cloudflare → My Profile → API Tokens → قالب Edit Cloudflare Workers).
  2. ربات Worker را می‌سازد و لینک اشتراک روی https://prostoreshop.site/sub/... می‌دهد (این دامنه برخلاف workers.dev در ایران فیلتر DNS نیست).
  3. کاربر لینک را در v2rayNG، Hiddify، Streisand یا NekoBox وارد می‌کند و Update می‌زند.
پنل‌های قدیمیپنل‌هایی که قبل از تنظیم رله ساخته شده‌اند هنوز Worker قدیمی دارند. در ربات روی هر پنل دکمه «اعمال IP تازه» را بزنید یا صبر کنید تا اتوپایلوت خودش آپدیت کند. لینک اشتراک عوض نمی‌شود.
۱۲

تست ChatGPT و Gemini از گوشی کاربر

با کانفیگ وصل شوید و در مرورگر این آدرس را باز کنید:

https://chatgpt.com/cdn-cgi/trace

خط ip= باید IP سرور شما و loc= کشور سرور باشد. چند بار رفرش کنید: IP نباید عوض شود. بعد gemini.google.com را باز و لاگین کنید.

نکته Geminiاگر قبلاً با IP ایران وارد اکانت گوگل شده‌اید، یک بار از اکانت خارج شوید، کش مرورگر را پاک کنید و دوباره وارد شوید. حالت ناشناس (Incognito) سریع‌ترین تست است.

عیب‌یابی

مشکلراه‌حل
ربات جواب نمی‌دهدdocker compose logs --tail 100. خطای BOT_TOKEN یا ADMIN_IDS یعنی .env را با nano /opt/autovless/.env اصلاح و docker compose up -d کنید.
Caddy گواهی نمی‌گیردرکورد A درست نیست یا ابر نارنجی است. journalctl -u caddy -n 50 را ببینید، DNS را اصلاح و systemctl restart caddy.
مینی‌اپ سفید می‌ماندcurl https://prostoreshop.site/api/health. اگر 502 داد ربات بالا نیست؛ docker compose ps.
ChatGPT باز نمی‌شودتست رله: curl --connect-to chatgpt.com:443:127.0.0.1:8443 https://chatgpt.com/cdn-cgi/trace. اگر جواب داد، پورت 8443 را در فایروال ارائه‌دهنده سرور (پنل دیتاسنتر) هم باز کنید و پنل را «اعمال IP تازه» کنید.
Gemini ارور منطقه می‌دهدtrace را از گوشی چک کنید. اگر loc درست است ولی ارور هست، IP سرور نزد گوگل بدنام است؛ IP یا لوکیشن سرور را عوض کنید و اسکریپت مرحله ۸ را دوباره اجرا کنید.
nginx بالا نمی‌آیدnginx -t و ss -ltnp | grep -E ':80|:443|:8443'. نباید nginx روی 80 یا 443 باشد؛ آن پورت‌ها مال Caddy است.

آپدیت و بکاپ

آپدیت ربات

cd /opt/autovless && git pull && docker compose up -d --build

بکاپ دیتابیس و تنظیمات

cd /opt/autovless && tar czf ~/autovless-backup-$(date +%F).tar.gz .env data

فایل بکاپ را با scp یا SFTP به کامپیوتر خودتان منتقل کنید. فایل .env و پوشه data شامل توکن‌ها و کلید رمزنگاری است؛ آن را جایی عمومی نگذارید.
